# Каталог анлоков и граф

`site/data/unlocks.json` — единственный редактируемый источник анлоков и их зависимостей. Интерфейс, полный граф и граф выбранного предмета строятся из него. Runtime не требует Python, npm, API или сервера приложения: всё вычисляется в браузере.

## Пространства данных

- `slotProgress(save, gameCatalog)` читает только собственные отметки, счётчики, completed-флаги, коллекцию и бестиарий слота. Значения секретов не влияют на эту модель.
- `evaluator.earned(id)` вычисляет подтверждение условия в текущем слоте. Оно может быть `satisfied`, `missing` или `unknown`.
- `evaluator.availability(id)` отдельно показывает доступность контента по `secretId`, без зачёта условия этому слоту. Без такого флага учитывается явная доступность по умолчанию или подтверждённое условие. Неизвестное состояние остаётся неизвестным.
- `evaluator.collected(node)` читает самостоятельный флаг коллекции для active/passive. У карт, рун, брелоков, персонажей и механик аналогичный флаг не хранится: результат `null`.

ID предмета, Save Secret ID, BossType, EntityType и индекс персонажа не взаимозаменяемы. Состояние Steam-аккаунта сайт не запрашивает. `secretId` разрешён только как справочный ключ доступности и не является типом условия.

## Узел

```json
{
  "id": "collectible:114",
  "kind": "collectible",
  "name": "Mom's Knife",
  "rank": "S",
  "order": 16,
  "catalog": { "kind": "passive", "itemId": 114 },
  "secretId": 43,
  "wikiUrl": "https://bindingofisaacrebirth.wiki.gg/wiki/Mom%27s_Knife",
  "unlock": {
    "description": "Победить Satan за Isaac.",
    "requirements": {
      "type": "all",
      "conditions": [
        { "type": "node", "id": "character:isaac" },
        { "type": "node", "id": "feature:sheol" },
        { "type": "mark", "character": "Isaac", "target": "Satan", "minimum": 1 }
      ]
    },
    "evidence": { "type": "mark", "character": "Isaac", "target": "Satan", "minimum": 1 }
  },
  "sources": ["https://bindingofisaacrebirth.wiki.gg/wiki/Mom%27s_Knife"]
}
```

`rank` отсутствует у служебной зависимости, которую нужно показывать в графе, но не как рекомендацию тирлиста. Один ID означает один объект во всех графах; общие зависимости не копируются. `catalog` нужен только для игровых предметов. Поддерживаемые виды узлов: `collectible`, `trinket`, `card`, `rune`, `pill`, `character`, `stage`, `boss`, `challenge`, `feature`.

Стартовое улучшение персонажа — отдельный `feature`, а не тот же collectible. Например, Holy Mantle (предмет) и The Lost: Holy Mantle (стартовое улучшение за 879 монет) имеют разные условия.

`rank` — ряд тирлиста: `S`, `A`, `B`, `C`, `D`, `F` или `OPEN` (открыты по умолчанию); `DEAD GOD` зарезервирован для единственной цели полного прохождения над S–F. `order` — позиция внутри ряда (0, 1, 2…), у записи с `rank` он обязателен. Ряды и их подписи заданы в `site/js/tier-ranks.js`; категорий руководства (`tier`) в данных больше нет, и валидатор отвергает это поле. `rank` не меняет доступность, условия или граф.

Ряды удобнее менять на сайте: перетащите предметы между рядами и нажмите «Выгрузить тиры (JSON)». Скачанный `unlocks.json` имеет тот же формат, что и `site/data/unlocks.json`, и заменяет его целиком; отличаются только `rank` и `order` перемещённых рядов. Без выгрузки раскладка хранится лишь в `localStorage` этого браузера, кнопка «Сбросить тиры» возвращает версию сайта. Исходные ранги однократно получены из категорий руководства скриптом `tools/migrate-tiers-to-ranks.mjs`.

`sourceNote` позволяет отметить уточнение автора руководства. `sources` содержит HTTPS URL, подтверждающие факты; не копируйте длинные описания эффектов или авторские оценки.

## Декларативные условия

| type | Поля | Значение |
| --- | --- | --- |
| `all` | `conditions: Condition[]` | Нужны все условия, в том числе вложенные группы |
| `any` | `conditions: Condition[]` | Достаточно одного из альтернативных путей |
| `node` | `id` | Открыть другую вершину; ссылка формирует зависимость графа |
| `mark` | `character`, `target`, `minimum: 1 or 2`, `label?` | Отметка персонажа: Normal/Greed или Hard/Greedier |
| `counter` | `id`, `atLeast`, `label?` | Собственный EventCounter слота не меньше порога |
| `collected` | `id: 1..732`, `label?`, `itemName?` | Фактический флаг подбора предмета в коллекции слота, без секретов |
| `challenge` | `id: 1..45`, `label?` | Записан completed-флаг испытания |
| `character_played` | `character` | У персонажа есть хотя бы одна собственная отметка |
| `boss_defeated` | `boss` | Положительный счётчик зачтённой победы или собственная отметка цели |
| `manual` | `key`, `label`, `reason` | Действие не сохраняется полностью; требуется явное подтверждение пользователем |
| `constant` | `value: boolean` | Явная доступность по умолчанию или заведомо невыполненное условие |

`label` объясняет действие на русском; сложная логика хранится структурой, а не попыткой парсить текст. Неизвестные типы не исполняются и отклоняются валидатором. Произвольный JavaScript и `eval` не используются.

`minimum=2` у `Greed / Greedier` означает Greedier. Не создавайте Greed и Greedier как два независимых сохранённых флага.

Канонические цели: `Mom’s Heart / It Lives!`, `Isaac`, `Satan`, `Boss Rush`, `???`, `The Lamb`, `Mega Satan`, `Hush`, `Greed / Greedier`, `Delirium`, `Mother`, `The Beast`. Имена персонажей берутся из `site/data/game-catalog.json`.

MOM_KILLS, counter 1 — победы над Mom’s Heart / It Lives!, **не Mom**. Условия «в одном забеге», «без смерти/возрождения», «зайти в шкаф», трансформации и точная история побед не должны заменяться похожим общим счётчиком. Убывающий текущий счётчик или серия не всегда доказывает исторический рекорд; в сомнительных случаях используйте ручной факт и пояснение.

## Прямое подтверждение результата

`unlock.evidence` — необязательное независимое доказательство результата. Если оно выполнено, прежние шаги отдельно подтверждать не нужно: записанная победа Satan за Isaac подтверждает Mom’s Knife, даже если сохранение не позволяет доказать способ первоначального открытия маршрута.

Прямое подтверждение может быть составным `all`/`any`, но **не содержит `node` и секретов**. Для Godhead это все требуемые Hard/Greedier-отметки The Lost, а не одна победа или итоговое достижение. Если действие не сохраняется, не придумывайте evidence. Ручной факт остаётся явной пользовательской отметкой и никогда не записывается обратно в `.dat`.

Отсутствие отметки у персонажа не доказывает, что им никогда не играли; `character_played=missing` означает лишь отсутствие такого подтверждения. Значение `unknown` не превращается в `false` или `true`.

## Два режима графа

По умолчанию выбран **прогресс этого слота**: `earned` без секретов. Альтернативный режим **доступность контента** использует `availability`, включая секреты; он помогает получить недоступный контент, но не считает его заслугой в этом слоте. Переключатель виден над графом.

Для A и C с общей зависимостью B:

```text
B ещё не выполнена:       B выполнена:
       B                     A    C
      / \
     A   C
```

Выполненная зависимость удаляется вместе с её предысторией; обход к её родителям не продолжается. A и C остаются, если их собственные действия ещё не выполнены. Вершины объединяются по ID, а не по имени.

Группы AND/OR показываются отдельными логическими вершинами, когда нужно связать несколько зависимостей. Условия действий подписывают рёбра, а полный список и состояния видны в боковой панели. Условие без зависимости отображается в панели отдельной вершины, а не получает фиктивный общий корень. Уже выполненная альтернатива OR исключает остальные альтернативы. Для не имеющей узлов альтернативы сохраняется отдельная вершина условия, чтобы не изображать необязательный путь обязательным.

`buildGraph` не меняет каталог. `layoutGraph` выполняет вертикальную топологическую раскладку, независимо от предметных условий: зависимости выше наград, широкие уровни переносятся в ряды по четыре блока. `graph-view.js` управляет масштабом вокруг курсора, перемещением блоков и фона, обновлением рёбер и анимированным восстановлением. Позиции действуют только в текущей вкладке и сбрасываются при смене сохранения. Циклический каталог отклоняется при загрузке и при сборке.

## Цель Dead God

`feature:dead-god` — единственная карточка верхнего тира. Базовый каталог — **Repentance**, без четырёх дополнительных секретов Repentance+. После загрузки Repentance+ чистый адаптер `catalog-profile.js` добавляет четыре ручных условия638–641 и меняет число условий на640, не изменяя исходный каталог. Rebirth использует собственную статистику и не применяет этот граф. Требования объединены AND: все остальные условия открытия (1–636) и подбор всех 717 видимых предметов коллекции. Отдельно показаны Death Certificate / 408 Hard/Greedier-отметок и все 45 completed-флагов испытаний — они также входят в общие условия.

`feature:dead-god-conditions` содержит ровно 636 помеченных `goalSecretId` условий в четырёх группах DLC. Это метаданные перечня, а не исполняемый тип достижения:223 ссылки повторно используют проверенные узлы,292 условия с точным соответствием отметкам/счётчикам проверяются по фактам,121 оставлено ручным. Их исходные формулировки сохранены. Неизвестный или перенесённый секрет не превращает их в выполненные действия. Составные исторические цели Platinum God,1001% и 1000000% не доказываются подсчётом флагов.

`feature:dead-god-collection` использует `collected` для каждого из 717 ID из `site/data/dead-god-collection.json`. Видимость подтверждена закреплённым игровым [items.xml Repentance 1.7.9b.J835](https://raw.githubusercontent.com/Derugon/TBoIR-resources/44ac14726d9904d2032c202283817a35a73bcd82/1.7.9b.J835/resources-dlc3/items.xml), SHA-256 хранится рядом. Скрытые 59,656,714,715 и отсутствующие ID исключены. Broken Glass Cannon474, квестовые части и Dad’s Note668 включены. Коллекция проверяется непосредственно по байтам сохранения, поэтому 474 учитывается даже при отсутствии имени в старом общем справочнике.

`feature:dead-god-challenges` ссылается на все 45 `challenge-complete:N`, а не на невидимые листья completed-флагов. `challenge:N` представляет доступ к испытанию; `challenge-complete:N` требует этот доступ и фактическое прохождение, а `unlock.evidence` проверяет собственный completed-флаг независимо от истории доступа. Поэтому уже открытое испытание не исчезает из задач до его прохождения. При неизвестном источнике доступа завершённое испытание остаётся доказанным. Награды и общий перечень условий ссылаются на те же completion ID; прямое evidence награды остаётся сырым фактом слота. В обоих режимах графа доступ к испытанию не подменяет его прохождение.

`tools/challenge-catalog.mjs` компилирует полный набор условий доступа из `data/challenges-repentance.json`, закреплённого по игровому challenges.xml (URL и SHA-256 внутри профиля). Числа `requiredUnlockIds` служат только ключами определения игровых правил при сборке. В runtime попадают обычные ссылки на фактические условия предметов/персонажей; флаги секретов не используются для прохождения. Поле `challenge: {id, role: "access" | "completion"}` — метаданные представления. Дополнительные узлы не меняют исходные места тирлиста.

Четыре узла цели воспроизводимо обновляются офлайн через `node tools/build-dead-god.mjs`: он компилирует только явно рассмотренные текстовые шаблоны в декларативные условия; runtime текст не разбирает. Сложные неподдержанные случаи остаются manual. Раскрываемые группы в панели показывают прогресс без постоянного вывода тысячи строк. Их открытое состояние и выбранный узел сохраняются при ручном подтверждении в текущем графе.

## Расширение

1. Найти игровой ID, тип, реальное условие, вики и источники; проверить исключения версии и стартовые улучшения.
2. Добавить узел и только отсутствующие зависимости в `site/data/unlocks.json`.
3. Использовать существующие ID зависимостей. Не дублировать B для каждого нового предмета.
4. Добавить локальный спрайт через `python3 tools/fetch_icons.py`; PNG и manifest включаются в репозиторий. Новому классу условий нужен отдельный evaluator и поведенческий тест; новый предмет обычно требует только JSON.
5. Запустить `npm run validate:data`, `npm test`, `npm run build`.

Готовый навык: `.agents/skills/isaac-unlocks/SKILL.md`. Он может добавлять предметы без редактирования интерфейса и движка графа.
