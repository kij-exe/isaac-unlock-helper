# Localization (EN / RU)

The website is in English by default. The switch in the header works before and after a save is loaded and offers Russian. The selected language is stored in `localStorage` under the `atlas-language` key; the theme setting is independent. If storage is unavailable, the language still switches for the current tab.

English is the source language everywhere in the repository: code, `site/index.html`, the canonical catalog `site/data/unlocks.json`, tools, tests and documentation. Russian exists only as website translations:

- `site/js/locales/ru.js` — interface messages keyed by their exact English text, plus parameterized patterns for runtime strings that embed numbers, names or filenames (`3 additional unknown flags`, save-parser errors, generated condition labels such as `Counter #3 ≥ 10`).
- `site/js/locales/ru-catalog.js` — Russian text for catalog presentation fields, keyed by the English source string.

`site/js/i18n.js` contains the translator and the presentation-layer localization. Static elements are translated in place without replacing DOM nodes, and their original English text is restored when switching back to EN. Dynamic HTML templates in the app use the `html` tag; text statuses use `i18n.text`. Text without a translation (item and character names, IDs, user input) is returned unchanged, and composite labels are translated only when every part is known, so English source text is never half-translated.

`unlocks.json` stays canonical and English. For the Russian interface, a copy is created in which only the presentation fields `name`, `label`, `description`, `reason` and `sourceNote` are translated. The edition profile is applied before translation, so the extra Repentance+ conditions are localized too. IDs, manual-confirmation keys, numbers, conditions, evidence, links, the source save and the statistics export never change. Item and character names stay in their original English. Search matches both English and Russian descriptions regardless of the selected language.

When adding an unlock or new interface text:

1. Write the English text in the catalog or the template.
2. Add the exact Russian translation: catalog text to `site/js/locales/ru-catalog.js`, interface text to `site/js/locales/ru.js`. For a repeated structure with numbers or names, add a parameterized pattern to `patterns` in `ru.js`; do not translate arbitrary IDs or user input.
3. Run `npm test`, `npm run validate:data` and `npm run build`.

`tests/i18n.test.mjs` checks that the catalog contains no Russian text, that every description, manual reason and note of both edition profiles has a Russian translation, that logic and links are unchanged, that the preference is stored, and that DOM localization reverts cleanly. Integration checks in `tests/upload-flow.test.mjs` exercise the real language-switch handler, uploads and errors, pages, the selected node, manual confirmations and zoom. The tests do not use any third-party translation service, and the site never sends player data to one.
